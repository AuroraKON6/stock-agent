## 1. 包 ID 与用户行为

R11（O 层；真实获准 provider 接入仍按授权边界另行）。

1. **query→result→consumed 单一权威**：`ConnectorQueryStore` 新表 `query_consumptions`（intent_id 主键——**一次意图至多一次消耗绑定**，重放不双绑；与预留/配额同库同事务边界）。
2. **文件 fixture 提供方**（任务书「先 Fake/file」首步）：`query_supply.FileFixtureTransport` 读宿主批准的 JSON 夹具（零网络零凭据），走**完整治理路径**（gate→用途→留存→目的地→原子预留→执行→归一化）；快照为版本化 in-code 契约（不冒充已评审 live 契约）。
3. **`attach_query_to_spec`**：一次受控查询接入任务供给——归一化结果入 `spec.query_results`、日线并入 `quote_snapshots`（provider=file_fixture 如实标注）；**回执列表**（supply 状态/意图/幂等键/消耗记录）随 spec 可审计；消耗绑定落 intake 库。
4. **供给状态三分（A52）**：`data_delivered / no_data / permission_denied / auth_rejected / suspended / replay / cache / gate_refused / budget / rate_limited`——绝不折叠成一个「空成功」；**失败的执行也如实绑消耗**（记录它产生了什么，哪怕是没有数据）。
5. **缓存命中分支**：不预留不消耗（无新计费），缓存归一化仍入供给，回执标 `cache_hit`。
6. **公告元数据=线索（A54）**：归一化行进 `announcement_leads`，**绝不**生成 `evidence_summaries` 条目——原件仍缺失，直到显式 vault 导入。
7. **重放语义（A53）**：同 api+params → 同幂等键 → intake replay——不触 provider、不预留、不二次绑消耗（测试用独立 transport 实证请求数为零）。
