## 候选 1：source-provenance-audit（承接 data-registry 的登记契约思想）

**保留现有 6 条全部不动**，新增以下（改写自 data-registry §2/§3，剔除其文件坐标/产物闸等交付物机制——本项目由 `evidence_facts.py` 的摘录绑定承担等价角色）：

1. **tier 分级与硬要求**：来源分 T1（官方一手原件）/ T2（权威聚合，注明聚合口径）/ T3（二手转载或供应商分析）/ T4（模型推断/人工判断）。**精确数值断言至少 T2；T3 的精确数需交叉核（两独立上游，同上游不同路由不算两条）**——核不出就降级为定性描述，不写那个数。
2. **口径五元组**：每个数值断言记录 unit / currency / basis（合并口径等）/ period_basis（单季 vs 累计——A 股财报默认累计，与美股单季披露不同，对照期须各自取数）/ adjust。**口径缺失的数值只能标"待补证"，不得与其他口径值直接对比**。
3. **派生木桶原则**：派生值（差值/比率/换算）的可信层级继承其最差输入的层级；`computation` 血缘里任何一个输入降级，派生结论同步降级，不因公式正确而豁免。
4. **展示改写登记**：凡对数值做了展示层归一（千分位、百分比化、单位换算重写），必须保留原值可回溯——成品中的改写形态若无法回溯到登记值，按未溯源处理。
5. **UNSOURCED 机械判据**：输出中的每个精确数字必须能对应到已绑定事实/已登记来源；对不上即 UNSOURCED，视同编造，修订前不得交付。

**角色映射**：不变（已分派 source-provenance-audit 的角色）。**预估增量**：约 +35 行纯文本，角色提示词增量可控（现 27 行 → 约 62 行，远低于需调全局上限的阈值）。

**不迁移**：data-registry 的 JSON schema 文件契约、locator 文件坐标、registry_gate 脚本纪律、批量登记流程——本项目的权威登记是 `evidence_facts`（vault 摘录绑定 + 计算血缘），两套登记簿并存会冲突（计划 §6.3 明令）。
