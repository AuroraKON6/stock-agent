## 1. 包 ID 与用户行为

R22（O 层；Dify 角色编排半边 = NOT_RUN，依赖 R17 未交付——与 R19 的 SDK 传输同政策：依赖未齐不做半吊子接入）。

本批交付的是任务书里**不依赖 Dify 的持久任务图治理半边**：任何编排器（今天的 Python 链、R17 之后的 Dify 角色）都必须穿过同一套约束，约束只活在一处（`stock_agent/subtask_graph.py`），不按编排器各写一份。

1. **提案先行**：`propose_subtasks` 先对整批提案做校验（fail closed），任何一个提案畸形 → 整批拒绝、一个子任务都不建（部分放行是范围 creep 的起点）。
2. **范围墙**：子任务不得加宽父任务——新 symbol、新案件、空问题全部拒绝；提案不带 symbol 时继承父范围。
3. **预算共享**：子任务以 `budget_reserve` 共享父的剩余模型尝试预算；存量预留 + 本批请求 > 上限 → 整批拒绝（`budget_exceeded`）。
4. **深度与扇出**：默认 depth ≤ 1、每父 children ≤ 3（常量可收紧）；**循环在构造上不可能**（子任务永远比父年轻 + 父链走到根），自指提案（parent=自身）仍显式拒绝，`_depth_of` 对损坏环有防御性终止。
5. **扇出计去重**：整批重复的提案不扩大任何东西——cap 按"新 (role, 问题身份) 键"计，纯重复批次不触发 `fanout_exceeded`，由去重通道返回。
6. **重复子任务**：同父+同角色+同问题身份（字母数字小写化，标点不区分）→ 返回 `duplicate_child`，不建第二个任务；创建走 `idempotency_key=subtask::{parent}::{role}::{qkey}` 双保险。
7. **取消传播**：`cancel_subtree` 深度优先取消父及全部非终态后代，**每个任务自己的 outbox 事件**；已终态后代历史原样保留（不删除——任务书回退条款"不删除已产生子任务"）。
8. **部分失败独立**：子任务是独立任务行——一个子任务终态失败，兄弟与父各自状态不动（测试实证）。
