## 1. 包 ID 与用户行为

R09（O 层交付；信号/kill/容器层随引擎可达后集中验收，见 §3）。

1. **常驻 worker 服务**：新 `worker_service.WorkerService`——一次一任务的认领循环；**停止 = 停止认领**：stop 置位后不再认领新任务，在途任务跑到持久状态后退出（排空不等于杀调用——中途强杀归 A43 崩溃恢复路径，由 R02 租约+fencing 承接）；空闲时尊重排空窗口或立即退出；`max_tasks` 有界运行。
2. **CLI 入口**：`python -m stock_agent worker-service`（`--worker-id/--ttl-seconds/--idle-sleep-seconds/--max-tasks/--drain-deadline-seconds`）——SIGTERM/SIGINT 触发优雅排空；**不隐式开启任何调度**（平台启动参数不得隐式变成 scheduler）。
3. **零副作用探针（A45 O 半）**：dify API server 新增 `GET /livez`（进程存活）与 `GET /readyz`（额外以**只读**方式打开任务库验证可读性）——零采集、零模型调用、零业务写入（outbox 行数跨探针不变已断言）。
4. **同计划时隙身份**：`scheduled_slot_key(schedule_id, planned_slot, scope_version)`——(调度 ID, 上海业务日, 规范 UTC 时隙, 范围版本) 的确定性身份；**跨午夜归属**（17:00Z=次日沪日 01:00，同一时刻两种写法同一身份）；崩溃/休市延迟后恢复同一时隙复用同一 key → 商店幂等去重而非重跑研究。
5. **每认领新连接**：`run_once` 每次 claim 开新 TaskStore 连接（R03 纪律）；`queue_depth` 只读供就绪探针。
