5. **用途与限流先于发送（A25）**：registry 新增可选机器可读 `purposes` 白名单（缺失=全部拒绝，fail-closed）；未登记用途或超出每分钟窗口时**不发任何请求**、不消耗预留。
6. **目的地宿主裁决（A24/F11）**：唯一批准目的地=宿主集成配置的精确 origin+path（HTTPS 强制）；真实 `UrllibTransport` 携带调用方自造 policy 指向别处 → 拒绝且不发送；注入 fake 是显式离线 seam。

## 4. 行为设计（与缺陷对应）

### F09 先查后写的竞态

`reserve_query` 单事务语义：同 key 已存在 → replay（不占用任何额度、不再派发）；分钟窗/源日限/组日限任一触顶 → 拒绝（零写入零发送）；否则插入意图 + 双计数 + 分钟窗事件一次提交。JSONL `query_intent` 仅在**首次成功预留**后追加（replay 不重复追加，审计与权威一致）。

### F10 留存权

`decide_retention(registry_status)`：正文通道（原始产物+缓存）= approved ∧ 未过期 ∧ body_retention_allowed；事实包内容 = external_send_allowed（供 R13 使用）；日志=恒允许（纯元数据）。governed 路径把 `artifact_root` 替换为 `None` 实现内存态运行——client 侧本就支持（`artifact_root is None` 不落盘），数据保留在 `result.artifact_contents`。

### F11/A24 目的地

`resolve_destination(integration)` 只从宿主配置构造（HTTPS 强制）；`assert_transport_destination`：UrllibTransport 的 policy 必须与批准值逐字相等（origin+path），不等 → `transport_destination_not_approved`，governed 拒绝在发送前；非 UrllibTransport = `offline_seam`（生产接线评审另行覆盖）。

### 缓存权利与刷新（A21/A22）

- 写：`purpose`/`rights_revision`（approved_at，退回 expires_at）/`as_of`/`expires_at`（TTL，配置 `kimi_sources.cache_ttl_seconds`，默认 24h）。
- 读：registry 门（已有）+ purpose 相等 + rights_revision 相等 + 未过期，四者全过才是命中；旧格式文档（无权利字段）一律 miss（fail-closed）。
- 过期/修订变化后的同 key 重查 → **replay**（拒读旧数据、不重计费）；需要数据 → `refresh=True`（新 uuid 后缀的线缆键+intake 键=新计费意图）→ 执行并按新 as_of/新修订覆盖缓存文档。

### A25 用途/限流先于发送

registry `purposes` 为空或缺目的 → `purpose_not_registered`，transport 零调用、零预留；分钟窗触顶 → `rate_limited`（reason=`rate_limited_minute`），同样零发送零预留。
