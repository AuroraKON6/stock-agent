## 8. 返工（KONM-75，2026-11-24）：逐次复核、授权取数、报告版本

两名非作者验证者在 `2a60beb` 独立复现了三处缺口，本次在 `stock_agent/research_library.py`、`stock_agent/task_board.py`、`stock_agent/task_detail.py` 修复。

1. **撤销逐次复核**。正常检索入口改为 `query_library(index, config, actor, ...)`：每次调用都按调用者当前获准的证据视图（共享金库 + 本人个人命名空间）重新复核传入的索引，缓存于撤销之前的索引在下一次查询即停止应答。全撤销 `evidence_revoked`、部分撤销 `evidence_partially_revoked` 均默认排除；`live_evidence_shas` 列出存活原件。`search_library` 降为纯过滤步骤，拒绝未经复核或旧 schema（`1.0`）的索引。索引 schema 升为 `1.1`，旧缓存需重建（重建无损失）。
2. **审计读取**。`include_stale` 只对研究名册中在岗、人类、持有 `quality_reviewer` 或 `compliance_officer` 角色的主体生效，由名册记录判定，响应以 `audit_granted` 回报。审计只解除“过期排除”，不扩大可见范围。
3. **授权取数**。`namespace`/`owner` 改由服务端归属记录（`task_input_bindings`，`via=personal_workspace_session`）解释，首个个人任务即 `personal`；`default` 为共享研究。**契约变化**：原实现按 `origin.research_occasion` 推导，首个个人任务被标为 `default`；该字段现保留为 `research_occasion`，仅用于时间线，不再表示归属。查询范围 = 共享研究 + 本人个人研究；`actor` 为空直接拒绝。payload 无法伪造归属（已测）。
4. **报告版本**。`report_version = rv1:<报告 schema>:<task_id>:<input_version>:<report_sha256>`，随 `report_schema_version`、`report_sha256` 出现在库条目和案件详情。`input_version` 是产生报告的不可变输入版本，`report_schema_version` 是报告载荷 schema，`report_sha256` 只覆盖报告正文（`REPORT_BODY_FIELDS`，规范 JSON 后取 SHA-256），因此事后追加的签收、质量判定和行版本变化不改变它。续研是新任务：自己的 task ID、从 1 起的输入版本和自己的报告版本，`prior_task_id` 指向原案；原报告保持不变。
5. **实际可访问入口**（会话模式）：
   - `GET /api/v1/library?query=&symbols=&task_id=&since=&until=&status=&include_stale=1`：身份取自服务端会话，请求中出现 `actor`/`owner` 返回 403，无会话 403，未挂会话存储 503。
   - `GET /api/v1/library/timeline?task_id=<原案>`：原案报告及以它为前案的续研。
   - `GET /api/v1/tasks/<id>`：案件详情新增 `report_version`。
   - 未做专用时间线页面；任务书 R20 的文件范围是研究库索引，页面接线留待后续。`/api/v1/tasks` 看板列表是 R14 的队列视图，未改动，不属于 R20 取数入口。
