## 1. 包 ID 与用户行为

R13（O 层交付）。

1. **不可变研究事实包**（新 `fact_bundle.py`）：一次外发研究尝试冻结一个包——绑定 task_id + input_version（R01 权威列）+ 证据文档（vault 验证投影）+ 宿主策略哈希；`bundle_sha256` 封印核心字段。
2. **宿主权利裁决（A60/A61）**：摘录事实以「vault 当前验证」为外发依据；带 `source_id` 的事实记录以「来源登记表当前外发权」为依据——registry 拒绝 → **排除+记录原因**，自称 `classification=public` **不提升任何权利**（自报值作为被忽略数据入记录）；无来源登记的事实记录没有宿主依据=排除。
3. **用前再验证（A62）**：`verify_research_fact_bundle` 对照**当前**状态——证据离开验证投影（撤销/未验证）或登记权利失效 → 整包失效；包哈希被篡改 → 拒绝。
4. **载荷哈希链（A63）**：worker 把 `approved_facts`（摘录选择器+事实记录）建包，仅**仍可投递**的包事实进入最小化模型上下文（`verified_facts`，内容截断 1000 字）；包记录**最终组装上下文的规范哈希**，`model_call.context_delivery.outbound_sha256` 显示同一哈希——模型实际收到的上下文=被批准的载荷可证。
5. **原始字节永不入包**：包内是已验证摘录文本+定位器/登记事实语句，无文档原始字节；排除项只进审计不进提示词。

## 4. 行为设计（与缺陷对应）

- 「分类来自宿主策略，不能信任 MCP payload 自报 public」（F15/R13 任务）→ 自报值仅作 `self_reported_class_ignored` 数据记录；裁决依据只有 vault 验证状态与 registry 外发权两源。
- 「每轮外发重新核查当前权利和撤销」（A62）→ 再验证对照**当前**投影/登记表，任何一侧失效即整包失效——旧权限不续命。
- 「改输入使旧结果失效」→ 包绑定 input_version（R01 列权威）：补证后 input_version 变化，旧包对新尝试无意义（重建即新包）。
- 「Pi 与 Dify 同一最小化事实语义」→ 语义在 `fact_bundle` 单点实现；Dify 面接入时消费同一模块（R16/R17）。

## 5. R04/R07 追修复（跨日预算键对称）

R07 把 `reserve_query` 的配额日键切到 `business_date_key`（上海日），但同文件 `quota_usage` 仍用 `_now(now).date()`（宿主本地/UTC 日）。16:00 UTC（沪午夜）后：写入沪日 N+1 桶、查询 UTC 日 N 桶——计数读 0。测试在跨界后运行即暴露（a23/quota-keys/kimi-budget 三处同根因）。修复：`quota_usage` 同用 `business_date_key`。这验证了任务书基础设施专项「UTC/上海时区跨午夜的预算归属」的必要性——它不是理论问题。
