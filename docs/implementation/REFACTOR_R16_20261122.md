# R16 Dify 整链接入（离线回放）

基线为 `3a50209`。本次交付单案回放流程、摘要清单和离线发布检查。容器验收另行完成。

## 单案流程

- `config/candidates/dify/flows/single-research-replay.yml` 通过受控 API 创建一次任务，收到可核对的任务回执后最多查询一次状态。发起方为同一业务意图保留同一个 `business_intent_id`，Dify 每次运行自己的 `sys.workflow_run_id` 只用于关联。流程固定使用 `replay`，无模型节点、插件或外部数据查询。
- 结果包含案件编号、业务意图编号、Python 任务编号和工作台相对路径。创建回执丢失时返回 `create_unconfirmed` 和工作台入口。状态查询失败时返回 `status_unconfirmed`，保留已确认的任务入口。后端返回 `failed` 或 `blocked` 时保留该状态，即使 Dify 工作流本身成功结束。反馈由用户在 Python 工作台提交。
- `status_only` 投影只返回任务编号、案件编号和状态。Dify 回放凭据只需 `create_research`、`read_research` 和指定的测试案件范围。

## 容器验收前置

沿用 DF-01 的 Dify 1.17.1 候选，核对了上游发布提交和 DSL 节点格式。本轮未启动容器。官方 Compose 的完整镜像摘要与独立网络配置仍待核验。现有 `deploy/compose.yaml` 的研究镜像默认命令只显示 CLI 帮助，且 Dify façade 仍限回环访问。正式接线需先提供明确的服务入口和隔离网关，将网关限制为 DSL 的两条 API 路由。

部署验收需保留 Dify 的 SSRF 防护。使用独立的 Compose 项目和测试状态目录，验证代理只通往指定网关、代码沙箱无出站、模型与数据凭据不上 Dify、上游传输层无额外自动重试。随后再验收 SSE 终态、重启和回放。停用新流程触发后，Python 任务及已有执行关联可供对账。
