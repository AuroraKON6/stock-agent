# R16 Dify 单案回放

首次实现基线为 `3a50209`。本文记录单案流程、镜像和网络静态验收，以及根据 KONM-17 运行证据追加的容器修正。

## 单案流程

- `config/candidates/dify/flows/single-research-replay.yml` 通过受控 API 创建一次任务，收到可核对的任务回执后最多查询一次状态。发起方为同一业务意图保留同一个 `business_intent_id`，Dify 每次运行自己的 `sys.workflow_run_id` 只用于关联。流程固定使用 `replay`，仅含原生开始、HTTP、条件和结束节点。
- 结果包含案件编号、业务意图编号、Python 任务编号和工作台相对路径。创建回执丢失时返回 `create_unconfirmed` 和工作台入口。状态查询失败时返回 `status_unconfirmed`，保留已确认的任务入口。后端返回 `failed` 或 `blocked` 时保留该状态，即使 Dify 工作流本身成功结束。反馈由用户在 Python 工作台提交。
- `status_only` 投影只返回任务编号、案件编号和状态。Dify 回放凭据只需 `create_research`、`read_research` 和指定的测试案件范围。

Docker Hub 直连 `registry-1.docker.io:443` 超时。通过本机 HTTP 代理重试后，Docker Hub 和 Weaviate 发布者注册表均返回清单。验证 Dify 组件原标签，以及 BusyBox `1.37.0`、PostgreSQL `15.19-alpine`、Redis `6.2.24-alpine`、Squid `6.6-24.04_beta`、NGINX `1.31.8` 等原浮动引用的替代标签。13 个镜像均固定发布者的清单索引摘要，索引均含 `linux/amd64`、`linux/arm64`。完整引用以 `compose.yaml` 的渲染结果为准。

### 渲染和网络

在仓库根目录执行。Docker Compose `v5.6.1` 的 `config --quiet` 无输出、退出码为 0。`config --images` 输出 19 条镜像引用，去重为 13 条且全部带摘要。`config --services` 输出 19 个服务。目标 Docker Engine 需支持内部桥接网络的 `gateway_mode_ipv4=isolated`。 [Docker 桥接网络文档](https://docs.docker.com/engine/network/port-publishing/#gateway-modes)

| 渲染网络 | 成员 |
| --- | --- |
| `ui_edge` | `nginx`，唯一的宿主端口为 `127.0.0.1:18080` |
| `core` | `agent_backend`、`agent_ssrf_proxy`、`api`、`api_websocket`、`db_postgres`、`nginx`、`plugin_daemon`、`redis`、`weaviate`、`web`、`worker`、`worker_beat` |
| `code_sandbox` | `api`、`api_websocket`、`sandbox`、`worker` |
| `workflow_proxy` | `api`、`api_websocket`、`ssrf_proxy`、`worker` |
| `replay_link` | `ssrf_proxy`、`stock-agent-r16-gateway` |
| `agent_control` | `agent_backend`、`local_sandbox` |
| `agent_proxy` | `agent_ssrf_proxy`、`local_sandbox` |

- 除 `ui_edge` 外均为内部隔离网桥。两个卷初始化服务均使用 `network_mode: none`。Python 服务共享回放网关的网络命名空间，仅监听 `127.0.0.1:8771`，回放状态和凭据登记文件只挂到相应 Python 服务。
- Dify HTTP 和 HTTPS 请求配置均保留 SSRF 代理。回放 Squid 只允许向 `stock-agent-r16-gateway:8770` 发出两条 DSL 定义的 POST 请求，其他请求默认拒绝。代理只尝试转发一次。网关再次核对方法和原始路径，通过回环转发且禁用重试。
- 代码沙箱关闭代码网络能力，并使用独立内部网桥。Agent 沙箱沿用内部控制通道，独立 SSRF 代理仅放行 Agent stub 和 Dify 文件端点。Dify 只能访问自己的 PostgreSQL、Redis 等内部依赖。研究业务库、模型及数据供应商凭据未出现在服务挂载或环境变量中。
- 样例凭据登记为空，环境文件里的值都是公开占位符。容器验收使用独立的测试实例值、经审查的流程摘要和仅限测试案件的服务令牌。凭据登记采用令牌哈希，范围只授予 `create_research` 和 `read_research`。Python 状态卷持久保存任务及关联，回放 API 仅接收 `replay` 新建请求和 `status_only` 查询。

## KONM-13 容器兼容修正

修复提交为 `84b34fe1fe62a6dbe32fdfa168e1e5a59da66c54`，接续草稿 PR #2 的 `agent/sol/758084bb9949` 分支，基线 `784864a`。Dify 1.17.1 的插件守护进程需要 `PLUGIN_REMOTE_INSTALLING_HOST`，本候选设为容器回环 `127.0.0.1:5003`。此端口没有发布到宿主。该版本要求 `SSRF_DEFAULT_MAX_RETRIES` 为正整数，Compose 设为最小值 `1`。该版本锁定的 Graphon 0.7.0 HTTP Request 节点显式以 `max_retries=0` 调用 SSRF 执行器，DSL 关闭节点重试，Squid 和 NGINX 保持原转发限制。 [上游 Compose](https://github.com/langgenius/dify/blob/8387590ace4a094de812b7847fc6a4c3a27cd52b/docker/docker-compose.yaml) · [上游锁定依赖](https://github.com/langgenius/dify/blob/8387590ace4a094de812b7847fc6a4c3a27cd52b/api/pyproject.toml) · [Graphon 0.7.0](https://pypi.org/project/graphon/0.7.0/)

原回放的代码节点请求启用沙箱网络，禁网实例会在创建任务前拒绝。更新后的原生 HTTP 节点用表单编码传参，Python 回放入口在原 JSON 契约之外接受这两张固定表单。Python 核对案件、Dify run 和任务 ID 后才发送可供原生条件节点读取的回执头。状态查询继续使用 `status_only`。流程摘要更新为 `sha256:18df408c8ada3e8af4ed0b5d0faaf9488ab2b00b1332e2b65c4a53f567a7e386`，发布校验拒绝代码节点、绕过创建回执的连线和暴露凭据的输出。
