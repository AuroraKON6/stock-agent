## 1. 包 ID 与用户行为

R03。用户/系统可见行为变化：

1. **Dify API 不再跨 HTTP 线程共享 SQLite 连接**（F06）：每个请求经 `workflow_service.request_store` 独立开连接，靠 BEGIN IMMEDIATE 串行化；并发创建同一业务意图恰产一个任务（A11）。
2. **主体验证回执原子核销**（F07）：签发入 `principal_verifications` 表（JSONL 保留审计副本）；`record_human_response`/`request_cancel` 在**同一事务**内核销——两个并发命令只有一个成功，败者明确落 pending（A12）。回执绑定 actor/task/action/command/expiry。
3. **凭据撤销下一请求生效**（F08）：网关不再持有凭据快照，每请求重读注册文件（路径在构造线程锚定，绕开 contextvar 陷阱）；撤销与恢复都在下一次调用立即体现（A16）。
4. **后端签发 dispatch 作为唯一执行凭证**：`workflow_dispatches` 冻结签发时的 task row generation、fencing、input_version、bundle、workflow 版本；提交校验全部绑定（A14），迟到旧 generation 拒绝（A15，generation 检查先于 binding——死世界的绑定比较无意义），伪造拒绝（A13）。
5. **候选接收与采纳分离**：`submit_candidate_result`（接收，可无 dispatch——回执显式标 `caller_self_reported_unverified`）与 `adopt_candidate_result`（采纳，仅后端验证过的 dispatch 回执可采纳；dispatch 恰好消费一次）。新 HTTP 路由 `/api/dify/v1/adopt-result`。
6. **越权查询不泄漏存在性**（A17）：保持统一 reason，新增覆盖。

## 4. 行为设计（与缺陷对应）

### F06 共享连接

`DifyGateway` 请求路径零共享连接：`__init__` 只记 `store.db_path`；所有操作经 `workflow_service.request_store`（开-用-关）。A11 用 6 线程屏障并发创建同意图验证（1 RECORDED + 5 DUPLICATE + 1 任务 + 行内一致），并发取消+反馈双线程验证无脏状态。

### F07 核销非原子

- 签发：`register_principal_verification`（表）+ JSONL 审计副本；同 id 同内容幂等、异内容冲突。
- 核销：`_claim_verification_in_txn`（守卫 UPDATE `WHERE used_at=''`）在 `record_human_response`/`request_cancel` 的任务事务内执行——核销与状态变更同提交/回滚。网关预检只产生友好 pending 原因；竞态败者从 store 拿到权威 reason（`principal_verification_already_used`）。
- 遗留兼容：仅存在于 JSONL 的旧回执首次使用时经 `issued_fallback` 迁入表中再原子核销；`used_at` 已置的旧 JSONL 记录不会被复活为新可用行（同 command 重放仍受任务级 command receipt/版本冲突约束）。

### F08 凭据撤销

`_credential_registry()`：注入凭据（测试 seam）固定；否则逐请求 `load_service_credentials(self._reload_config)`，`_reload_config` 的路径是构造线程解析的绝对路径（处理线程 contextvar 缺失也正确）。A16 双向验证（撤销→下一请求 401；恢复→下一请求通过）。

### 候选采纳（任务书「后端签发…结果提交验证全部绑定；接收与采纳分开」）

- `issue_workflow_dispatch`：后端签发，冻结 generation（=签发时 task row version）/fencing/input_version/bundle/workflow。
- `validate_workflow_dispatch`（只读）：unknown → task_mismatch → already_consumed → **generation_stale** → binding_mismatch → task_not_active。
- `consume_workflow_dispatch`（写事务内复验+守卫 UPDATE）：采纳恰一次；并发第二采纳 409 `dispatch_already_consumed`。
- 网关：`submit_candidate_result(dispatch_id=...)` 强验证；无 dispatch 的回执标记 `caller_self_reported_unverified`（可留存、永不作为采纳凭证——「caller 自报 attempt 只是数据」）。`adopt_candidate_result` 要求 dispatch 绑定回执；采纳账本事件（JSONL）+ outbox（store）。
