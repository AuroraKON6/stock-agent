## 2. [P1] 账本误写后删除不是合规恢复证明

依据：`docs/implementation/BASELINE.md:308` 与当前 0 字节账本。

交付方记录了误写真实事件后，移除事件、对象、投影。该做法违背项目对审计历史只追加、不得删除或覆盖的约束。记录事故是必要的，但不能使删除行为自动变为合规。

历史 health 的 events=0 是某个时点的投影，不是误写前一刻的完整备份；当前为空也不能证明删除范围准确。因此本次不指控已经删除真实研究资料，但同样不能认定恢复无损、可审计。

下一步由 Zcode 提供：误写发生时间、触发测试、实际解析的配置路径、受影响文件范围、误写事件 ID/原始哈希、误写前可获得的文件清单/备份、删除命令或操作记录、相关运行输出。不要输出密钥和私人原文。

保全现存日志与残留证据，不再修改历史账本；不得为补齐证据伪造原事件、恢复时间、操作人或审批。无法找回的部分明确标记无法验证，由真实负责人审查。任何后续修正应采用经审阅的补偿/隔离方案，不自动重建一份“干净历史”。

技术防复发要求：测试入口必须强制临时根，启动时检查所有写路径是否落在隔离区；测试身份不能获得正式目录写权限。加入一项故意保留默认 vault 路径的负例，要求在写入前失败。仅靠每个夹具作者记得覆盖路径不够。

## 3. [P1] 真实文档哈希仍可给任意摘要和外案引用背书

位置：`stock_agent/research_worker.py:191`、194 行。

现在确实验证了原件字节，但 worker 把权威文档集合压缩为 hash set；只要用户提供的 sha 在集合内，就保留输入中的任意 ref 和 summary，并附加 `vault_verified=True`。没有验证 ref 对应 document_id、该文档是否关联本案件，也没有将摘要绑定到原件提取文本/已审阅摘要版本。

隔离复现：

1. 用真实 `import_official_document` 在临时区导入“收入下降”的合成文档。
2. 使用该真实哈希，另给引用 ID `unrelated-case-ref`，摘要改成“收入增长十倍”的合成相反说法。
3. 调用实际 `build_safe_research_context`。
4. 得到 `ARBITRARY_REF_AND_SUMMARY_ACCEPTED True; vault_verified=True`。

没有向任何外部模型发送这些内容。

修复标准：保留权威 document_id、signal/case 关联和实际允许外发的证据投影；摘要需有提取片段位置/摘要版本及自身哈希等可核验来源，不要将对象哈希当摘要真实性证明。人类追加意见应作为人类判断单独标识，不能随附一个真实哈希后变为官方事实。

验收负例：正确哈希+错误文档 ID、正确文档+无关案件、正确文档+被替换的摘要、投递后摘要版本变化，均不得作为已验证来源陈述通过。允许模型推断，但必须与来源事实明确区分。

## 4. [P2] 浏览器“焦点保持”断言允许丢焦点

位置：`tests/browser_board_check.py:80`。

`focused2 in ("notes", "BODY")` 把已经复现过的失败状态 BODY 也视为成功。因此 6/6 只能证明当前宽松断言通过，不能证明重排保住焦点。

本次没有据此声称当前 UI 必定丢焦点；指出的是验收证据不足。

修复标准：断言 activeElement 是原输入节点，而不仅是同名元素；同时验证 value、selectionStart/selectionEnd。重排输入应确实改变两个或更多任务的相对顺序。补真实 HTTP 提交、SSE 更新与重连场景，不能只通过直接调用 render 钩子宣称端到端完成。
