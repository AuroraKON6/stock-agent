3. **引用存在但数字不符 → 规则指出**（A32）：带引用声明中的数字 token 若未出现在**实际投递给模型的上下文**（vault 投影摘要 + 显式未验证人工注记 + 已批准行情快照）中，标记 `number_mismatch`、扣分、写入 review_note 提示人工复核——指出但不静默信任、也不自动拒收。

## 4. 行为设计（与缺陷对应，F13）

- 「只校验给出的引用属于集合，不强制具体事实引用」→ 三段式：(a) 声明分类（数字=具体；推断标记豁免但可见）；(b) 具体声明零引用 → 不可完成（A30）+ 草稿保留为 gap（A31）；(c) 带引用数字与**投递文本**逐 token 比对 → 不符标记（A32）。
- 核对基准是 `build_safe_research_context` 的**真实输出**（worker 内以最终 safe_context 计算），不是输入侧的自称——与「引用必须属于当前批准上下文」同一权威。
- 数字 token 比对是子串级启发（全角归一）：匹配不证明正确，不匹配必被指出——A32 的「规则指出」定位；最终判断保留给人工复核。
- worker 集成点在协议校验（引用属于批准集）**之后**、broker/人工/完成**之前**——两道检查互补：协议管「引用真实」，质量管「该引用的有没有引用、引用的数字对不对」。
