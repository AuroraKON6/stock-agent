## 状态路径与入口

两套配置从开始就指向同一个 `scheduler_ownership.state_dir`，分别声明 `legacy-powershell` 和 `container-worker`。注册表与源业务快照分开放置。旧侧由 `run_daily_research.ps1 -Mode daily -TriggerSource scheduled` 的显式时隙参数进入，新侧由容器定时器调用 `scheduled-task-submit`。两侧使用带时区的计划时刻、schedule ID 和 scope version 计算同一个业务意图键。提交在注册表锁内检查 owner、外来心跳和冻结标记，然后写任务库。现有无显式时隙参数的 Windows 定时入口在业务步骤前检查配置中的调度权。队列消费者 `worker-service` 可继续处理已接单的任务。

在 `6d2bd3b` 复核发现，意图键已统一为 UTC，任务内容比对仍使用原始时间字符串。任务库现在在现有事务内以 UTC 比对已落库和本次提交的 `scheduled_slot.planned_slot`，保留原始任务内容与输入快照。比对保留时刻的微秒精度，继续检查研究问题和其他请求内容。

`cutover-gate` 与 `cutover-switch` 按同一规则解析注册表、任务库和容量检查根目录，默认从任务库所在文件系统检查可用空间。切换在注册表锁内执行四项门检，成功后递增 generation、记录审计、移除退役 owner 的心跳。回退额外要求冻结接单、排空 queued/leased/running，然后由 `cutover-reconcile-rollback` 全列核对源快照中的任务和 outbox 行。清单记录增量、当前任务库摘要、generation 和本次 freeze ID。切换前复验清单，过去的清单或对账后发生的写入会阻止回退。

回退时旧入口接管已对账的恢复库，保全原业务树，同时延续新侧已有的意图键和 outbox 游标。正式窗口须验证两侧实际配置都指向共享注册表，旧入口恢复配置引用已经对账的兼容库。

## PowerShell 停用与恢复

`set_scheduled_tasks_enabled.ps1 -Disable -RecordPath <path>` 在停用前记录每个任务的状态，逐项确认停用后更新同一记录。正式回退须使用同一路径运行 `-Enable`。它依据停用记录恢复本次确认停用的任务，保留原先已禁用、原先缺失以及停用未确认的任务。中断后可在恢复开始前用同一路径重跑 `-Disable` 核实待确认项。维护窗口内须避免对同一任务做并行管理操作。

在 PowerShell 7.4.13 Linux 容器内执行 `tests/r25_scheduled_tasks_mock.ps1`，模拟原先启用、原先已禁用和缺失任务。干跑零写入，注入第二项启用任务的停用失败后，只有第一项实际停用的任务被恢复。原先缺失项在回退前出现且保持禁用，重跑恢复也没有重新启用后来独立禁用的任务。模拟替换了 Windows 的三个 Scheduled Tasks cmdlet，保留脚本实际的参数、分支及记录读写。
