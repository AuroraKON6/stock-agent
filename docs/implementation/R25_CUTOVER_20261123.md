隔离环境下对任务书 R25 的完整演练：排空 → 静止快照 → 隔离恢复 → 对照 →
唯一调度者切换 → 同时隙跨重启重放（不重复）→ 冻结回退 → 增量对账 → 切回
owner。全程使用两个独立临时状态卷（`r25-legacy`、`r25-new`）与合成任务；零
真实供应商（compose 网络 `internal: true`），零真实 PowerShell 任务操作
（旧入口的"停用"是明确标记 `simulated: true` 的注册表记录，真实生效步骤是

设计取舍：**注册表按状态树各存一份**——快照/恢复移动的是业务状态，注册表由
切换流程显式带入新树（R24 bundle 内容不变）；回退后旧树注册表停留在快照时
刻（gen 1），新树记录完整代际史（gen 1→2→3）。**schema 回退检查是钉死配对
策略**：SQLite 对更新形状的文件不会拒绝打开，门检比较运行时 schema 与切换
计划钉死的 `rollback_supported_schema` 上限（默认 1.3），任一侧变化须重估。

## 6. 计费与重复口径说明（诚实边界）

本演练全程 replay 模式（`model_call.called=false`）：预算账本 0 笔、调用链 0
条是真实读数，"计费不重复"的证明对象因此是**结构不变量**——同一 intent 重放
后 `invocation_attempts_total`、`budget_linked_attempts_total`、
`research_round` 事件数与 outbox 交付数全部零新增。真实供应商计费路径
（`reserve_model_attempt` → attempt 链）由 R02/R09 用例与门检的 unknown 检查覆
盖，真实成本不重复的端到端证据需在正式切换后按真实调用核验。

## 7. 真实切换尚缺项（正式窗口前须完成/决策）

1. **镜像重绑**：`scheduler_ownership.py` 与 CLI 子命令目前只读挂载演练；正式切换前须以受控构建入镜像并重绑摘要（复用 `scripts/build_image.sh` A39 守卫）。
2. **R08 状态卷正式修复**（KONM-27 发现 2/3）：挂载点/属主/REQUIRED_STATIC_PATHS 入镜像，否则正式容器数据不持久。
3. **API 暴露形态决策**（发现 4）。
4. **真实个人流程证据**（R15）：本演练为合成证据；KONM-23 的 live/human 验收仍在父任务。
5. **真实 PowerShell 现状与授权**：旧 `StockAgent_*` 任务的实际存在性、正式数据目录、真实运行窗口——`set_scheduled_tasks_enabled.ps1 -Disable` 须在窗口内由人执行并把记录对齐注册表标记（去掉 `simulated`）。
6. **静止窗口规程**：`cross_file_atomic_snapshot=false` 未变，正式切换保持全静止窗口操作（排空→确认无写者→快照）。
7. **回退增量处置**：演练把增量留在新树并落清单；正式回退时这批增量的重放/丢弃需人工决策记录。
