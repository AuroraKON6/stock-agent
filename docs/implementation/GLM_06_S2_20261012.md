# GLM-06/07 交付报告（2026-10-12，第二批）：案件时长预算 + 问题任务幂等 + task-create 迁移

执行：GLM。范围：三个边界清晰的小改动——①单案件总时长预算（计划 §4.2，GLM-07 前置补齐项）；②问题任务幂等按问题身份而非上下文字节；③`task-create --from-symbols` 迁移到统一 intake 服务（GLM-04 遗留项）。

## 工作包与具体用户流程

1. **时长预算**：live 多轮研究受 `task_runtime.case_time_limit_seconds`（默认 600，下限 60）约束；预算耗尽在第 N 轮边界如实 failed（错误含 "case time limit"），不会开始下一轮模型调用，重试不延长预算。
2. **问题幂等**：同一问题文本+标的+模式返回既有任务——即使重建的公开上下文字节不同（真实运行中缓存/时间戳每次变化）。实现为显式幂等键 `question::{sha256}::{symbols}::{mode}` + store 层"同逻辑请求"豁免（与事件键豁免同构：origin.kind=question 且 question_sha256 一致）。
3. **CLI 迁移**：`task-create --from-symbols` 现走 `ensure_question_task`（业务规则单点）；`--spec` 路径保持旧行为。

## 正负用例（先失败后实现）

- 预算：伪造时钟让第 2 轮边界超限 → 只调用 1 次模型、failed、错误含 "case time limit"、行状态 failed；默认 600 秒正常单轮成功。
- 幂等：注入每次字节不同的 drift_marker 模拟真实上下文漂移 → 仍 DUPLICATE 同任务；改问题文本 → 新任务；CLI 双跑同问题 → 恰 1 任务且 origin.kind=question。
- 测试设计说明：确定性临时环境下上下文天然相同，幂等必须显式注入漂移才算数（首轮测试因夹具确定性而"假绿"，已修正）。
