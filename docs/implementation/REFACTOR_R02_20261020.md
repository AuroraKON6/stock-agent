## 4. 行为设计（与缺陷对应）

### F02 超时误入普通重试

- 分类三分：`sent=no`（可证未离机：preflight 标签、连接被拒/DNS 文本标记）、`sent=yes`（供应商明确应答：HTTP 状态标记、parse/audit 阶段标签）、`unknown`（默认：超时、进程死亡期间、无标记的派发后异常）。
- 任务级映射：no→`fail(retryable=True)`（受 max_attempts 有界）；unknown→`mark_blocked`（last_error 指明 attempt 与"manual reconciliation required"），**不进队列**；yes→`fail(retryable=False)`（终态；重试是上层决定）。
- 预算：unknown 时不释放、不冲抵（预留事件即占用，A08）；对账也不回滚预留历史——`confirmed_not_charged` 只解锁重试，不改账。

### F04 调用中无心跳

- `HeartbeatRunner`：守护线程按 `max(5, ttl//3)` 间隔调 `renew_fn`；失败记录 `last_error`、置 `healthy=False` 并停止。
- `lease_heartbeat`：为每次调用**新开一个 TaskStore 连接**（避免与 worker 线程共享连接的事务交错），退出时关闭。
- worker 门禁：任一心跳失败后（`heartbeat_state.healthy=False`），即使轮间 `renew_lease` 成功也不再发起新外发；已完成的在途调用结果仍照常记录（它可能已计费）。
- deadline：`call_deadline_seconds = min(供应商超时, 案剩余)`；案耗尽时在 dispatch 前抛 `ModelCallNotSent`（未发出，安全重试语义）。

### A09 崩溃恢复

- `recover_abandoned` 先以独立事务跑 `recover_stale_invocation_attempts`：dispatched→`outcome_unknown`（请求可能已发），prepared→`failed_known/sent=no`（可证未离机）；随后重开任务事务并**复查状态**（防恢复期间续租竞态）。有 unknown 的任务改判 `blocked`（不再重排），无 attempt 或仅 prepared 的沿用原重排/过期语义。

### A10 对账

- `reconcile_invocation_attempt(attempt_id, actor, resolution, reason, requeue_if_blocked)`：resolution 限 `confirmed_charged|confirmed_not_charged`；reason 必填；仅 `outcome_unknown` 可对账；同 resolution 重放幂等，改口冲突；`requeue_if_blocked` 仅在任务仍为 blocked 时经 BLOCKED→QUEUED 放回（记录 `task_requeued` 事件）；事件 `invocation_reconciled` 落 outbox。
