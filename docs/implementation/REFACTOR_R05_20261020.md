## 1. 包 ID 与用户行为

R05。

1. **自由公式字符串不再是确定性计算**（F14 停止条件根除）：computation 契约改为**白名单命名操作**（`sum/difference/ratio/yoy_growth/convert_unit`）；formula 字符串被构造层直接拒绝——「仅凭 formula 字符串就标确定性计算」从结构上不可能。
2. **声明与已验证回执分离**：`build_fact` 记录的是计算**声明**（值+操作+输入 ID，纯数据）；`facts_service.verify_computed_fact` 按解析出的输入事实**实际值**用 Decimal 重算，值/单位匹配才允许 `attach_verified_receipt` 落「已验证计算回执」（含真实输入值/单位/期间、舍入规则、结果 decimal 文本）——失败验证不落任何回执。
3. **数值卫生**：NaN/Infinity（float 或十进制字符串）在事实构造、转换助手、计算器三层全部拒绝；缺失值是错误而非 0；除零明确拒绝而非无穷。
4. **期间混算门禁**：事实新增 `period` 字段（参与 fact_id——同数不同期是不同事实）；可比操作（sum/difference/ratio/yoy_growth）跨期间默认阻断，显式 `allow_mixed_periods=True` 可放行且**记入回执**可审计。
5. **单位换算精确**：元/万元/亿元走 Decimal 幂十因子精确换算，回执保留原单位/目标单位/期间（口径不因换算丢失）。

## 4. 行为设计（与缺陷对应，F14）

- 「只验 formula 字符串及 ID 形式」→ 契约层拒字符串 + 执行层只认白名单操作 + 验证层重算比对，三层缺一不可。
- 「接受 float 未拒 NaN/Infinity」→ `_finite_number`（构造）/`_input_value`（计算，含 `"NaN"` 十进制字符串）/`convert_amount_to_cny` 三层拒绝。
- 回执保留真实输入（fact_id+value+unit+period）与 `decimal_text`，链条可再审计；`allow_mixed_periods` 与舍入参数显式入回执。
