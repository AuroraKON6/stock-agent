## 1. 包 ID 与用户行为

R17（O 层；Dify 传输 = NOT_RUN，依赖 R16 部署，与 R18 SDK/R19 传输同政策）。

任务书的 R17 形态：Dify 调用**受控角色 API** 驱动"分析→反证→综合"。本批交付该 API 的 Python 侧全部内容并以 replay 验证——测试扮演编排器（正是将来 Dify 所在的位置），与 R15 replay 骨架同一范式。新增 `stock_agent/role_execution.py`：

1. **冻结流制品**：`prompt_artifact` 把每个角色的提示词文本钉到 sha256；`define_role_flow` 把分组结构与全部提示词摘要钉到一个 `flow_sha256`。同制品重建摘要逐字节相等；提示词文本任何改动=新摘要=新候选（A77 基石）。同版本号换摘要注册=显式冲突（`flow_version_conflict`，防"画布偷偷改但版本不动"）。
2. **批准绑摘要不绑名字**：`FlowRegistry.approve` 只覆盖一个具体摘要；旧批准对改动后的候选自动失效（`approval_digest_changed`），必须重新批准新候选——规则变更只产候选。
3. **模式切换=新输入版本**：`bind_role_flow` 走 `store.bump_input_version`（本批新增的公共原语）——绑定是 input_version+1 的受管变更，事务内写不可变快照+审计事件，历史版本原样可回放。换绑只允许显式升级（同摘要重复绑拒、降版本拒）。
4. **互斥（A76）**：三层防线——`claim_next(exclude_role_bound=True)` 让 Python 整链认领路径跳过绑定任务（默认参数行为逐字节不变）；worker 入口对误交接的绑定任务返回 `refused_role_flow`（零模型调用、零状态推进，状态停留在 leased）；R22 `propose_subtasks` 克隆父 payload 时剔除 `role_flow`（绑定只属于根，子步骤是普通可认领任务，其身份走 `role_step`）。
5. **步骤=有界子任务**：`execute_role_step` 经 R22 图建步骤子任务（范围/深度/fan-out/预算帽全部生效），注入冻结提示词，走标准 worker 边界执行（replay 单发、R06 质量门照跑——测试实证含数字的未引用草稿照样被拦成 blocked），运行后从持久化 payload **重验提示词摘要**（注入后被篡改=步骤作废）。子任务继承父 execution_mode（本批修复：原先 replay 根会生出 live 子任务）。
6. **循环有界、不双计费（A78）**：已成功步骤拒绝重跑（`step_already_succeeded`，无第二子任务无第二计费）；终态失败步骤拒绝静默重试（`step_failed_needs_decision`——诚实的补救是显式决策，如 `cancel_subtree`）；非终态在途步骤返回 `step_in_progress` 不产孪生；组序强制（`group_not_current`，综合不能抢在分析/反证前）。
7. **根收口带溯源**：`finish_role_flow` 只在全部角色步骤成功后完成根任务；根自身零模型调用，output 携带每角色{task_id, summary, output_sha256}溯源，model_call.steps 记录步骤→任务链接。

## 7. 开发期缺陷（本批抓到并修复）

1. `propose_subtasks` 未传 execution_mode——replay 根生出 live 子任务（worker 走真实外发路径失败后重排，测试当场上露）。子任务现继承父模式。
2. 子任务克隆父 payload 会把 `role_flow` 带下去（触发认领排除+worker 拒绝，步骤永远跑不动）——R22 克隆时剔除，绑定只属根。
3. 测试种子"按 v2 完成"含数字 2 被 R06 质量门按"未引用数字声明"拦成 blocked——**门是对的**（角色步骤与整链同门同口径的实证），改用无数字种子。
