## 1. 设计决定（与计划的对应）

| 计划要求 | 实现 |
| --- | --- |
| "优先复用现有接口，不先新建一套 REST 框架" | 纯服务层 `DifyGateway` + stdlib `ThreadingHTTPServer` 薄绑定（与 task_board 同模式，无框架）；权威写路径全部复用：`TaskStore.create_task`（幂等创建）、`record_human_response`/`request_cancel`（版本与命令幂等）、`budget_guard.may_start_model_call`（预算回执） |
| "创建研究：输入研究范围、输入版本与幂等键；返回 task_id 和状态" | `create_research(token, ...)`；不等待模型；`origin={kind:"dify", dify_run_id, workflow_version}` 写入任务 payload（运行关联）；重复输入 DUPLICATE（负向#1：重复点击/平台重试=一个逻辑任务） |
| "查询研究：只返回该调用主体获准查看的" | `research_status`：字段白名单最小化视图 + case 范围过滤 + 不存在/越权统一 `task_not_found_or_out_of_scope`（防枚举）；附 `budget` 回执与 `poll` 上限提示 |
| "读取事实包：冻结版本和可引用集合" | 后端 `issue_fact_bundle`（按 case+input_version 冻结、bundle_hash）；内容仅投递 classification=public 且 external_send_allowed 的事实，其余只留引用+排除原因；`revoke_fact_bundle` 后读取与引用均阻断（负向#7，Dify 缓存不能继续用） |
| "提交研究候选结果：绑定 attempt、流程版本与输入哈希；校验引用和 fencing 后提交，拒绝旧结果覆盖" | `submit_candidate_result`：绑定 task/dify_run_id/workflow_version/bundle_hash/citations/task_version/attempt_receipt；workflow_version 必须在配置批准清单（防免审热更新）；引用⊆投递集合；cancelled/terminal 任务拒收（负向#3）；精确重放幂等返回原回执、同 run 不同内容冲突 |
| "提交反馈/取消：必须经过验证的用户主体、command_id、expected_version，不能仅接受 Dify 传来的 actor 字符串" | 服务凭据 ≠ 真人授权：受保护动作需后端签发的**主体验证回执**（`issue_principal_verification`，Dify 凭据无法铸造——不在任何 scope 中）；无验证/伪造 actor → 记入 pending 账本、绝不执行（负向#4）；回执单命令单用、短时效、每次使用入审计 |
| "服务认证与真人授权分离" | `dify_access.py`：注册表只存令牌 SHA-256（timing-safe 比较，永不落明文）；scope 五类 + case_scope；缺文件=空注册=全拒（fail-closed，同 source_registry 教义） |
| ID 绑定链 `case_id/task_id/input_version/attempt_id/dify_run_id/workflow_version` | create 回执与 status 视图回传 dify 绑定；候选结果回执同时记录六元组中的五个 + attempt_receipt（attempt 由 worker 侧预留事件承载） |

**过程事故（已修复并入设计）**：调试期间两次在守卫外直接运行复现脚本，审计账本被写到
真实工作区 `data/dify/access_log.jsonl`（内容仅调试记录，无业务数据）——已删除并确认 `data/dify/` 不存在。
根因：socketserver 处理线程不继承 contextvar 路径覆盖（已用最小脚本实证）。修复：网关构造时
一次性锚定五个账本绝对路径，处理器线程不再调用 `project_path()`。此教训已写入模块注释。

## 6. 回滚方式

全部为加法，回滚 = 停用，无数据迁移：

1. 配置层：生产配置无 `dify` 键 → 网关全拒（enabled=false），HTTP 绑定不启动即不存在。
2. 代码层（如需彻底移除）：删 `dify_access.py`、`dify_api.py`、`dify_api_server.py`、
   两个 test_dify_* 文件、示例 JSON；还原 cli.py 两处窄接线（`git checkout 06f079e -- stock_agent/cli.py`）。
3. 已生成的 `data/dify/*.jsonl`（若有真实运行）是审计账本，保留不删；不触碰任何既有账本。
