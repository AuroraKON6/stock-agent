## 1. 包 ID 与用户行为

R18（O 层；官方 MCP SDK 采用与真实服务器对接 = NOT_RUN）。

1. **连接器策略层**（`connectors/policy.py`）：fail-closed manifest（未知字段/非法传输/非 HTTPS 远端/缺失受众全拒）；**工具可见性=白名单**（A81：服务器多广播的工具是不可见的新面，绝不自动生效）；**调用方凭据禁运**（A82：Authorization/X-API-Key/Cookie/proxy-authorization 出现在调用参数即拒绝，连接器只以自己的策略凭据+记录受众认证）；**端点钉扎**（A83：构造期解析 DNS——私网/回环/链路本地/组播/保留地址全拒，未解析也拒）。
2. **MCP 薄客户端**（`mcp_client.py`）：initialize→tools/list→tools/call 的 JSON-RPC 公共面（协议版本不匹配即握手失败）；**工具结果大小封顶**（A84：超限=有界拒绝，载荷丢弃不解析）；**注入文本=数据**（A85：毒文本逐字透传、工具集不扩张）；**调用中断连**：已发送后断连→`connection_lost_after_send`+人工对账提示，绝不静默重试（与 R02 语义一致）；`MemoryMCPTransport` 进程内假服务器承载全部规则（零网络零子进程，守卫友好）。
3. **HTTP 连接器**（`http_client.py`）：exact-origin POST——构造期 DNS 钉扎 + 请求期凭据仅自持 + **3xx 一律拒绝不跟随**（重定向=目的地变更）+ 响应封顶 + 畸形有界失败。
4. **支持矩阵（A80）如实报告**：`mcp_stdio`/`http` = VERIFIED_O（进程内假）；`mcp_http`/`mcp_sse`/官方 SDK = NOT_RUN（SDK 是新运行时依赖，需来源/许可证登记+锁定安装，未做就不冒充支持）。

## 8. 返工修订（2026-11-24，claudecode）

依据 KONM-79 两份独立复验合并出的 F1–F6 修订；基线 `46e391c`，仅改本包与 `tests/test_refactor_r18.py`，测试从 15 项增至 34 项。第二轮复验（`87c68b0` 之后）补：预撤销连接器握手前零 RPC、凭据独立目的地绑定、image/resource 必填载荷校验。

| 项 | 修订 | 关键接口 |
| --- | --- | --- |
| F1 · A82 调用方凭据 | 除 `caller_headers` 外，递归检查工具 `arguments`（含嵌套 dict/list）中的 authorization/x-api-key/cookie/proxy-authorization 等键，命中即 `caller_token_forbidden`，发送计数 0；合法参数不受影响。 | `ConnectorPolicy.forbid_caller_tokens_deep` |
| F2 · A82 身份与受众 | 连接器身份改为可信配置绑定的 `ConnectorCredential(connector_id, audience, token, destination, expires_at)`；`destination` 是独立于策略文档的批准 origin，策略地址变化后旧凭据会被拒绝；发送前校验连接器 id、受众、有效期与目的地，缺失/错误绑定一律 `credential_not_bound`/`credential_audience_mismatch`/`credential_expired`/`credential_destination_mismatch`，不发送。MCP 把身份+受众作为 auth 呈现交给 transport 适配器；HTTP 同时交付标识与受众并只用自身凭据。 | `ConnectorCredential`, `bind_connector_credential` |
| F3 · A83 目的地 | URL 由解析后的 origin + 校验过的 path 重建（拒绝 `@`、`#`、`\\`、`//`、非 `/` 开头、控制字符），并复核最终 scheme/netloc/hostname；每次请求把已批准地址传给 transport 适配器；策略目的地变化时重新钉扎。 | `approved_request_url`, `HTTPConnector.post(addresses=…)` |
| F4 · A83/A85 断连 | 传输适配器可抛 `HTTPTransportError(phase=before_send|after_send|unknown)`；未标注异常按 `transport_delivery_unknown`。`after_send` 与 `unknown` 均附 `manual reconciliation`，始终只尝试一次。MCP 的 after_send + 对账语义保留并复测。 | `HTTPTransportError` |
| A81 · 即时撤销 | 新增 `ConnectorRegistry`（线程安全、可 `reload`/`revoke`）；客户端可接收策略提供者，对同一活跃实例撤销后 `list_tools()` 直接返回空且不再外发，工具调用/HTTP 发送计数均为 0；预先撤销的连接器在构造时即拒绝，不发送 initialize。 | `ConnectorRegistry`, 客户端 `policy` 提供者 |
| A84 · 响应 schema | MCP 逐条校验 content 条目（对象、非空 type、允许类型；text 需字符串，image 需非空 data+mimeType，resource 需非空 resource.uri），HTTP 要求顶层为 JSON 对象；超限或畸形一律受控错误、不产出可用结果。 | `MCPClient.call_tool`, `HTTPConnector.post` |

边界不变：仍为 O 层合成（进程内假 MCP、假 HTTP transport、注入解析器）；真实 transport、官方 SDK、真实 MCP 服务器与部署镜像为 **NOT_RUN**。`support_matrix()` 的五行由测试逐行锁定（含 `mcp_http`/`mcp_sse` NOT_RUN）。
