### 修正 1：版本锚 1.7.2 → 1.17.1（必须修正，非偏好）

**证据链**（2026-10-13 查阅）：

- [Dify GitHub Releases](https://github.com/langgenius/dify/releases)：最新稳定版
  **v1.17.1**（2026-09-10）；版本线 1.15.0(6/25)、1.16.0(7/17)、1.16.1(7/28)、
  1.17.0(8/25)、1.17.1(9/10)。
- Human Input 节点版本线：[官方博客](https://dify.ai/blog/the-human-input-node-bringing-human-judgment-into-automated-workflows)
  确认 **1.13.0 引入**（2026-02/03）；[1.14.1 发布说明](https://dify.ai/blog/dify-1.14.1-workflows-become-a-team-asset)
  确认 **Human Input API 1.14.1 加入**；Releases 确认 **1.17.0 支持嵌入
  Iteration/Loop**（1.17.1 修复编辑器残留）。
- 结论：**1.7.2（2025 年线）完全不含 Human Input 节点**，而首批候选
  `capabilities_required` 自身列有 `human_input_node`——原锚定自相矛盾，不满足
  DF-01 验收项"确认 Human Input、API、流程导出能力适用于选定版本与版本权益"。
- 修正：`DEPLOYMENT_CANDIDATE_VERSION = "dify-1.17.1-candidate-1"`；新增
  `capability_facts` 段记录能力线与来源；`human_input_node` 能力条目补
  `available_since`。新增 2 项测试锁定该约束
  （`test_pinned_version_satisfies_human_input_capability_line`、
  `test_environment_measured_closes_the_quota_open_question`）。

### 修正 3：部署候选细化（方案 A 推荐）

- 形态定为**现有 WSL2 Ubuntu 内原生 Docker Engine + compose v2**（非 Docker
  Desktop：避免其商业许可评估与更重宿主集成）。Windows 原生多进程方案拒绝。
- 1.17.1 官方 compose 服务清单已核对（api/api_websocket/worker/worker_beat/
  web/postgres/redis/sandbox/local_sandbox/plugin_daemon/agent_backend/
  ssrf_proxy×2/certbot/nginx/weaviate:1.39.2）；宿主仅暴露 80/443/5003，全部
  改回环绑定。
- **浮动 tag 风险**：官方 compose 对 nginx/squid/certbot/postgres/redis/busybox
  用浮动标签，违反本项目固定基线规则——DF-03 安装时改为具体版本+**镜像摘要**；
  当前无 docker 无法解析 digest，如实登记为 DF-03 待办。
- Weaviate 1.27→1.39.2 分阶段升级警告仅影响既有部署迁移；本项目全新安装不适用。

| 原 open question | 核实结论 |
| --- | --- |
| 选定版本与许可条款逐条核对 | Dify OSL = Apache 2.0 + 禁多租户 SaaS + 须保留品牌；本项目单租户自托管内部用途允许；按项目规则登记 **REVIEW_REQUIRED**（Agent 不代批）。[仓库](https://github.com/langgenius/dify) |
| Human Input / API 可用性 | 1.17.1 具备（节点 1.13.0+、API 1.14.1+、循环内嵌 1.17.0+）。**已核实的使用限制**（设计必须吸收，[官方文档](https://docs.dify.ai/en/self-host/use-dify/nodes/human-input)）：邮件链接任何持有人可回复且先到先得 → 持链接≠已验证身份；Web app 表单不适用于 Trigger 启动的工作流 → 第一阶段后端事件驱动路径不能只押注 Human Input 表单，需后端案件入口链接兜底；超时默认 3 天须显式连接超时分支为"返回案件入口" |
| 端口/磁盘/内存配额 | 见 §环境实测补测段 |
| （新增待办）SSRF 放行机制 | [ssrf 模板源码](https://github.com/langgenius/dify/tree/main/docker/ssrf_proxy)核实：Squid 默认拒绝私网 + 兜底 deny all，经 include 片段（dify_allow_private.conf）精确放行后端 host:port——与计划"不关全局防护、精确放行内部 API"一致 |
