**发现的真实缺口（R25 切换前须决策）**，按严重度：

1. **候选镜像缺共享库，任务库代码根本跑不起来（已修复待复核）**。R08 候选镜像把 `python:3.12-slim` 的 `/usr/local` 叠加到 `node:22-slim` 上，但 `_sqlite3`/`_ssl` 链接的 `libsqlite3.so.0`/`libssl.so.3` 只在 python 基础镜像里：构建产物内 `import sqlite3`、`import ssl` 直接 ImportError。已在本分支 `fee7795` 于 Dockerfile 运行时层补装 `libsqlite3-0 libssl3` 并重建（新摘要 `sha256:acad75a8…`），**镜像内容变更需规划师复核接受并重新绑定摘要**。
2. **R08 compose 的状态卷挂载点与应用实际写路径不一致**。应用相对路径（`data/...`）按 `PROJECT_ROOT`（镜像内 `/app`）解析，不看 `APP_*` 环境根；`deploy/compose.yaml` 把状态卷挂在 `/var/stock-agent/state`，任务库实际会写进容器可写层 `/app/data`，既不持久也不进备份。且镜像既不创建 `/app/data` 也不给属主。本次演练把卷挂到 `/app/data` 并以 root 运行绕开（`deploy/testing/r25_precheck.compose.yaml` 有说明）；正式修复属 R25 切换包范围。
3. **R24 备份的 REQUIRED_STATIC_PATHS 不在镜像里**。`pyproject.toml`、`requirements.lock.txt`、`config/watchlist.example.json` 是备份必需静态输入，但镜像只 COPY 了 `stock_agent/`、锁文件（仅 linux 版）与 pi_runtime——镜像内裸跑 `backup-create` 会报缺件。演练以只读挂载这三个文件绕开；镜像应补齐或备份默认源需调整。
4. **API 回环 Host 信任让 compose 网内调用全部 403**。`dify_api_server` 对非回环 Host 一律 `403 non_loopback_request`（R10 精确信任按设计工作）：跨容器探针实测被拒。R08 compose 设想 API 只服务内网，但当前实现下网内任何调用方都会被拒——R25 前需明确 API 的正式暴露形态（本地端口映射/回环代理或受控 Host 白名单）。
5. **构建包装脚本在 macOS 不可用（已修复）**。`build_image.sh` 的 A39 摘要钉守卫把 `{64}` 传给 BRE grep，BSD grep 视为字面量导致永远 BLOCKED；另外包装脚本要求宿主有 `python` 命令（本机只有 `python3.12`，用 PATH 垫片绕开）。前者已在本分支 `e56afb7` 加 `-E` 修复。
6. **测试隔离运行器在 macOS 上误伤自身清理路径**。`run_isolated_tests.py` 的审计钩子拦 `os.remove`，而 macOS `shutil.rmtree` 以相对名+dir_fd 递归删除，守卫把相对名按 CWD（仓库根）解析后误拒，使 `test_backup_restore.py` 4 项预期失败用例报 ERROR。同一批用例直接 `python3.12 -B -m unittest tests.test_backup_restore` 全过（19/19）。属宿主环境伪影，不是基线行为回归；Codex 在同基线全量跑看到的 21 errors 与此类一致。

### 3.1 backup_restore 的 4 项错误定位

4 项全部是「故意投毒、预期 create_backup 返回 FAIL」的用例：失败路径里的 `_safe_remove_tree` → `shutil.rmtree` 在 macOS 走 fd 递归（`os.unlink(相对名, dir_fd=…)`），运行器审计钩子把相对名按 CWD=仓库根解析后误判为写仓库而拒绝，`BackupRestoreError` 未被映射成 FAIL 结果。独立复现（见 §8 仓库外一步复现脚本）确认纯 BSD rmtree×审计钩子交互。同命令在容器/Linux 不受影响（rmtree 走路径式删除）；R24 报告当时全过与此一致。**判定：环境伪影，非基线回归**；修复建议（审计钩子跳过带 dir_fd 的 os.remove 或按 fd 解析真实路径）留给规划师排期。

### 4.1 A41 排空（真实 SIGTERM）

```
docker compose … run -d --name r25-worker drill python -m stock_agent worker-service \
  --config data/config/watchlist.drill.json --worker-id w-a41-drain --ttl-seconds 60 --idle-sleep-seconds 0.3
sleep 0.8; docker stop -t 60 r25-worker
```

- 种子：1000 条合成回放任务，全部 queued（2.64MB 库）。
- SIGTERM 落在处理中：`docker stop` exit 0，容器 `ExitCode=0`、`OOMKilled=false`。
- drain 报告：`{"processed": 411, "by_status": {"succeeded": 411}, "stopped": true}`。
- 停后库面：`{"queued": 589, "succeeded": 411}`，411+589=1000 精确对账；**无 leased/running 残留，无人再认领**。
- 子进程回收：replay 模式无派生进程；容器退出即回收。

### 4.2 A42 心跳（容器内独立连接续租）

`heartbeat` 子命令：claim（ttl 15s）→ `lease_heartbeat` 包住 12 秒合成调用（零网络零模型）→ 第 6 秒从第三个只读连接采样 → `run_research_task` 落终态。

- `beats=2, healthy=true`；租约到期时刻 claim 时 `02:44:54+00:00` → 调用中 `02:44:59+00:00`，**调用中可见延后**；最终 `succeeded`。

### 4.3 A43 强杀与 stale lease

```
docker compose … run -d --name r25-crash drill python /drills/r25_precheck_drill.py crash   # claim 后持租约睡眠
docker kill r25-crash     # 宿主 SIGKILL：容器 ExitCode=137
```

- 踩坑记录：容器内 `os.kill(os.getpid(), 9)` 无效——该进程是 PID 1，同命名空间对 init 的 SIGKILL 被内核丢弃（首次实测 exit 0 才发现）；改由宿主 `docker kill` 得到真实 137。驱动脚本已按此实现。
- kill 后：任务仍 `leased`、worker=`w-a43-crash`、租约行原样，**崩溃后零新事件**（不自动删锁、不重发）。
- R23 投影同期：`stale_leases=1, inflight_leases=1`。
- 显式 `recover_abandoned`：重新入队、worker 清空、`last_error="lease expired; task requeued by recovery"`；二次崩溃的同任务在 attempts 耗尽时正确转 `expired`（有界重试语义）。
- 迟到写入：死 worker 用旧 fencing token `complete` → `TaskTransitionError` 拒收，任务 status/version 不变。

### 4.4 A44 存储异常

- **DB busy**：`dbbusy_holder` 容器持 `BEGIN EXCLUSIVE` 50 秒（marker 确认已持锁）→ worker：`sqlite3.OperationalError: database is locked`（`claim_next` 的 `BEGIN IMMEDIATE`），exit 1，无部分状态；释放后 `PRAGMA integrity_check=ok`，1000 任务账目完整（413 succeeded+1 expired+586 queued）。
- **磁盘满**（独立 `diskfull` 服务，8MB tmpfs 有界测试存储）：填充至剩 8KB → worker 在 `claim_next` 的 `_commit` 处 `sqlite3.OperationalError: database or disk is full`，exit 1；**事务回滚，3 任务全部仍 queued**，integrity ok。

### 4.5 A45 只读探针

- `probe` 服务起 `dify_api_server`（gateway disabled、注入空凭据），同容器回环调用：`/livez`、`/readyz` 各 3 次全 200，`store_read_only_open=true`，**任务 1000/事件 2247 计数跨 6 次探针不变**。
- 跨容器（`http://probe:8770`）实测 6 次全 `403 non_loopback_request`——发现 4 的直接证据。
