## 3. 首批工作单

### Z-001：基线盘点

交付 `docs/implementation/BASELINE.md`，内容必须包括：

1. 当前 HEAD 是否存在、工作树状态数量，不含秘密或私人文件内容。

验收：现状能逐项引用代码或报告；不产生业务事件、不调用外部模型、不改变业务 Go/No-Go。

### Z-002：运行与数据边界

### Z-003：运行身份与失败恢复

先编写故障用例，再修改协调代码。针对共享写入、长任务续租、manifest 接线、重复 signal 未研判、部分产物完成、并发文件名六类风险逐项核实。

要求：

## 4. 首个产品切片

Z-001 到 Z-003 完成后，按照以下顺序实施，不一次注册六个空壳 Agent：

1. 一个持久 research task 与 outbox，包含输入版本、状态、事件序号、取消和重试记录。
2. 一个可用来源的公开事件，附带真实时间和证据；许可未清楚则使用明确标记的离线回放。
3. 一个 Pi 分析节点，输出 schema 合法、证据可核验的研究结论和一个具体人工问题。
4. 一个只读任务页，显示排队、执行、成功、失败、等待人工，以及模型实际状态。
5. 一个人工反馈接口，带身份、幂等和 expected_version；个人签收不等于机构批准。
6. 一次有证据的取消/断线/重启恢复演示。

满足上述闭环后再加行情图、新闻聚类、Planner 并行路由和 Agent Fleet。前端可以先用历史 replay 开发，但必须显眼区分 replay/live，不能伪造“正在运行”。

## 5. 实施边界

- Pi 继续禁工具、动态扩展、动态 skills；模型提出 JSON 意图，由 Python allowlist 执行。
- 模型每轮实际 payload 都做治理，不把内部 roster、限制名单、本地路径或密钥发送出去。
- 自由 URL、Shell、任意 Python 代码、任意路径不作为研究动作参数。
- 不增加下单、调仓、券商登录或交易 SDK。
- 不自动安装第三方插件；只学习固定版本代码或单独做候选 PoC。
- 不自动更新技能锁、模型、来源批准，不伪造角色和人工评分。
- 不删除旧 reports/data，不重写 JSONL 审计历史。
- 不用大规模重构掩盖实际业务故障。

## 6. 技术选择

Python 业务模块继续复用；SQLite 支撑首期单机任务，采用事务任务 + outbox + 单 writer；既有领域 JSONL 保持原权威性。

新增 Web API 与前端仅在基线确认后引入：候选 FastAPI + React/TypeScript + SSE + Lightweight Charts。没有必要先迁移 PostgreSQL、搭 Kafka 或引入额外 Agent 图框架。

具体依赖版本需检查许可证、Windows 兼容、当前 Python 版本和现有锁；先形成 ADR，再精准安装。对每一项新增依赖说明“现有模块不能解决什么”。
